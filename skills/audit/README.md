# audit

## Назначение

`audit` анализирует проект, документы или workflow и возвращает рекомендации в чат. Скил не правит файлы.

## Ответственность

- Прочитать релевантный локальный контекст.
- Найти противоречия, размытые зоны ответственности, риски, пробелы и устаревшие формулировки.
- Отдать пользователю структурированный отчёт с приоритетами.
- Отделять факты от выводов и рекомендаций.

## Связь с конвейером

`audit` вызывается по требованию на любом этапе. Его вывод может стать входом для `feature`, `planning`, `improve`, `docs`, `markov` или ручной правки, но сам он ничего не меняет.

## Почему граница такая

Аудит ценен как независимый взгляд. Если он сам начинает править файлы, исчезает различие между диагностикой и исполнением.

## Входной контекст

- запрос пользователя
- кодовая база проекта
- `./workflow/`
- документация проекта
- отдельные файлы, явно указанные пользователем

## Выходные артефакты

- только ответ в чат

## Не делает

- Не меняет код.
- Не меняет документацию.
- Не меняет workflow-артефакты.
- Не создаёт отчётный файл без отдельной просьбы.
- Не делает git-операции.

## Критерий готовности

Пользователь получает ясную карту проблем и следующих действий, а рабочее дерево не меняется.
