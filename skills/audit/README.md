# audit

## Назначение

`audit` анализирует проект, модуль, механику, алгоритм, архитектурное решение или страницу и возвращает в чат **сжатый, привязанный к коду** диагноз. Скил строго read-only: рабочее дерево не меняется.

Планка — не «перечислить всё, что можно улучшить», а «назвать то, что реально важно, доказать и остановиться». Чистая область — валидный результат: скил скажет об этом одной строкой, а не выдумает находки ради объёма.

## Что изменилось

- **Гейт ложных срабатываний.** Каждая находка проходит проверку: точная переформулировка → доказательство `path:line` → реальна ли в этом коде → назван ли конкретный сценарий вреда → не стиль ли это под видом риска → self-check на LLM-bias. Не прошла — выбрасывается, а не разжижается в filler.
- **Сжатый формат.** Находка ≤ 3 строк (severity, `path:line`, факт, влияние, фикс). Тяжёлый язык, абзацы на находку и общие советы без названной дыры — запрещены.
- **Линза по типу области и намерению.** Проект / модуль / механика-алгоритм / архитектурное решение / страница; расследование бага против «понять как работает + рекомендации».
- **Глубина вместо симптомов.** Одна доказанная корневая причина важнее пяти подозреваемых; для механик трассируется реальный поток данных и управления.

## Место в конвейере

Вызывается по требованию на любом этапе. Конвейерной рекомендации следующего шага не даёт — рекомендации и есть его продукт; приоритизированные next steps могут вести в `feature`, `planning`, `improve`, `docs`, `markov` или ручную правку.

## Входы

- запрос пользователя (область и намерение аудита)
- проектные инструкции, `./workflow/`, документация, код и тесты в рамках области
- файлы, явно указанные пользователем

## Выходы

- отчёт в чат: область, ключевой вывод, находки по severity (P0–P3) — каждая с доказательством, влиянием и фиксом; при необходимости корневая причина; 1–5 приоритизированных шагов
- отчётный файл — только по явной просьбе с указанным путём

## Не делает

- Не правит код, документацию и workflow-артефакты.
- Не выполняет мутирующие команды (установка зависимостей, генерация и т.п.).
- Не делает git-операции.
- Не раздувает не-проблемы и не даёт общих советов без названной дыры.
