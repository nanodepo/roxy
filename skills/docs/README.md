# docs

## Назначение

`docs` создаёт и обновляет пользовательскую и техническую документацию
проекта: корневой `README.md` и страницы `./docs/{concept,spec,tech}/`.
Фиксирует текущее состояние продукта — читатель понимает проект без знания
истории разработки.

## Место в конвейере

Работает в конце ветки фичи, обычно после `test`. Завершает конвейер: в
feature-update режиме помечает фичу `[/]` в `./workflow/PLAN.md` и в отчёте
называет следующую фичу из плана, если она есть.

## Входы

- Реализованный код проекта или фичи.
- `./workflow/PROJECT.md`, `VISION.md`, `ROADMAP.md` — если есть.
- В feature-update режиме: `feature.md` фичи, плюс `plan.md`, `design.md`,
  `tests.md` — если есть.

## Выходы

- `README.md` и страницы `./docs/concept|spec|tech/`.
- Сверенные соседние страницы доки: устаревшие утверждения заменены текущими.
- Docs-хвосты и статус `[/]` (feature-update) в `./workflow/PLAN.md`.
- Финальный closing sweep затронутых страниц по дисциплине скила `markov`.

## Не делает

- Не пишет код и тесты.
- Не пишет audit-отчёт — анализ расхождений принадлежит `audit`.
- Не переписывает workflow-артефакты фичи.
- Не ведёт историю изменений: только настоящее время, без «было/стало».
- Не выполняет git-операции.

## Когда применять

Поведение реализовано (и обычно протестировано), и его нужно зафиксировать в
документации: «напиши документацию», «обнови доку», «задокументируй фичу».
