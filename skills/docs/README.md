# docs

## Назначение

`docs` создаёт или обновляет пользовательскую и техническую документацию проекта. Скил фиксирует текущее состояние продукта, а не проводит аудит.

## Ответственность

- Создать документацию с нуля, если её нет.
- Обновить текущую документацию на основе реализованной фичи.
- Поддерживать корневой `README.md` и страницы в `./docs/{concept,spec,tech}/`.
- Писать документацию как текущее состояние, без биографии изменений.
- Добавить в `PLAN.md` только служебные docs-хвосты, если обнаружены пробелы документации.

## Связь с конвейером

`docs` обычно работает после `test`, когда поведение уже реализовано и проверено. Он читает проектный канон и фичевые артефакты, но не становится владельцем этих артефактов.

## Почему граница такая

Документация фиксирует текущее состояние продукта. Анализ расхождений и рекомендации принадлежат `audit`; docs-хвосты только отмечают недостающие документы.

## Входной контекст

- реализованный код
- `./workflow/PROJECT.md`
- `./workflow/VISION.md`
- `./workflow/ROADMAP.md`
- `./workflow/features/{slug}/feature.md`, если документация обновляется по фиче
- `./workflow/features/{slug}/plan.md`, `design.md`, `tests.md`, если они есть

## Выходные артефакты

- `README.md`
- `./docs/concept/*.md`
- `./docs/spec/*.md`
- `./docs/tech/*.md`
- служебные docs-хвосты в `./workflow/PLAN.md`

## Не делает

- Не пишет audit-отчёт.
- Не меняет код.
- Не пишет тесты.
- Не переписывает workflow-артефакты фичи.
- Не делает git-операции.

## Критерий готовности

Документация помогает понять текущее назначение, поведение и устройство проекта без чтения истории разработки.
