# feature

## Назначение

Превращает сырую просьбу пользователя в самодостаточный feature brief —
`./workflow/features/{slug}/feature.md` — и регистрирует фичу в
`./workflow/PLAN.md` со статусом `[ ]`. Brief — повествовательный текст: суть и
мотивация, ожидаемый результат, границы. Размер пропорционален сложности фичи;
для простой достаточно пары предложений.

## Место в конвейере

Открывает фичевую ветку workflow. В финале рекомендует следующий шаг: простая
фича — сразу `implement`; UI-фича с нетривиальным UX — `design`; остальное —
`planning`. Следующие скилы не вызывает.

## Входы

- запрос пользователя (аргумент скила или текущее сообщение)
- канон `./workflow/`: `PROJECT.md`, `VISION.md`, `ROADMAP.md`, `PLAN.md`,
  `DESIGN.md` для UI-запросов
- существующие брифы в `./workflow/features/` (проверка дублей)

## Выходы

- `./workflow/features/{slug}/feature.md`
- строка фичи `[ ]` в `./workflow/PLAN.md`
- рекомендация следующего шага в чате

## Порядок работы

Исследование (запрос + workflow-контекст + проверка дублей) → накопившиеся
вопросы одним батчем, рекомендованный вариант первым → синтез с учётом ответов
→ запись брифа и регистрация в PLAN.md. Вопросы закрываются до записи: в готовом
брифе открытых вопросов нет.

## Не делает

- Не пишет `plan.md`, `design.md`, `tests.md`, `NN-task.md`, код, PRD,
  acceptance criteria; не принимает решений о реализации, архитектуре,
  дизайне, тестах.
- Не делает git-операций.
