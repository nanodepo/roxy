# implement

## Назначение

Пишет продуктовый код для одного определённого скоупа — одной задачи
`NN-task.md`, одного пункта `plan.md` или простой фичи по `feature.md` — и
синхронизирует фактический прогресс в чекбоксах и статусах.

## Место в конвейере

Обычный этап после `task`; работает и напрямую по компактному `plan.md` или
простому `feature.md`. Контракт с `task`: при наличии задач читается карта в
`plan.md` и ровно одна выбранная задача — не полный план и не соседние задачи
(кроме явно названных зависимостей). Дальше: остались задачи — снова
`implement`; всё реализовано — `test`; нет тестируемой логики — `docs`.

## Входы

- выбранный `./workflow/features/{slug}/NN-task.md` + карта в `plan.md`,
  либо пункт `plan.md`, либо простой `feature.md`
- `design.md`, `DESIGN.md`, `ARCHITECTURE.md`, `PROJECT.md` — по мере
  отношения к изменению; кодовая база проекта

## Выходы

- изменения в продуктовом коде в рамках скоупа
- актуальные чекбоксы: статус задачи, карта задач в `plan.md`, хвосты
- статус фичи `[x]` в `./workflow/PLAN.md`, когда весь скоуп реализован
- финальный closing sweep: уборка осиротевшего кода в затронутой области и
  нормализация затронутого кода по дисциплине скила `markov`

## Не делает

- Не планирует сложную фичу и не переписывает план вместо `planning`/`improve`.
- Не нормализует и не переформулирует `NN-task.md`, `plan.md`, `feature.md`,
  `design.md`: в них правятся только чекбоксы, хвосты и пункт, разошедшийся с
  реальностью. Closing sweep касается кода, а не формулировок задачи и плана.
- Не пишет `tests.md`, тестовый код и документацию — это `test` и `docs`
  (существующие тесты запускать можно).
- Не делает широкие рефакторинги вне скоупа и git-операции.

## Когда применять

Пользователь просит реализовать задачу или фичу, написать код или продолжить
реализацию по существующему плану.
