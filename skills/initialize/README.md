# initialize

## Назначение

`initialize` подготавливает проект к работе агентного конвейера. Скил создаёт минимальную структуру `./workflow/`, фиксирует технический контекст проекта и оставляет служебные хвосты для следующих проектных скилов.

## Ответственность

- Создать `./workflow/`, если структуры ещё нет.
- Создать или обновить `./workflow/PROJECT.md`.
- Создать базовый `./workflow/PLAN.md`.
- Добавить в `PLAN.md` служебные хвосты на `roadmap`, `architecture` и `design-guideline`, если соответствующих артефактов нет.

## Связь с конвейером

`initialize` запускает проектный workflow. После него обычно идут `roadmap`, `architecture` и `design-guideline`, потому что они наполняют уже созданную структуру содержанием.

## Почему граница такая

Bootstrap должен быть дешёвым и безопасным: он создаёт место для канона, но не принимает продуктовые, архитектурные и визуальные решения. Служебные отметки в `PLAN.md` не делают `initialize` владельцем следующих этапов.

## Входной контекст

- Корень проекта пользователя.
- Существующие файлы стека: package manifests, lock-файлы, конфиги, docker-файлы, CI-файлы.
- Ответы пользователя, если стек нельзя определить автоматически.

## Выходные артефакты

- `./workflow/PROJECT.md`
- `./workflow/PLAN.md`
- директория `./workflow/archive/`
- директория `./workflow/features/`

## Не делает

- Не пишет `VISION.md`.
- Не пишет `ROADMAP.md`.
- Не выбирает архитектурный паттерн.
- Не описывает дизайн.
- Не создаёт фичи.
- Не делает git-операции.

## Критерий готовности

После выполнения в проекте есть рабочая `./workflow/`-структура, техническая справка и список следующих незакрытых проектных шагов.
