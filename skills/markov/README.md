# markov

## Назначение

`markov` нормализует по законам Маркова то, на что указал пользователь: файлы, каталог, архитектурную концепцию или материал прямо из разговора. Законы субстрат-независимы — скил переводит их на язык цели и меняет её напрямую, а не выдаёт рекомендации вместо правки.

## Ответственность

- Принять указание на цель: путь, несколько путей, каталог, glob, концепцию («слой Actions», «как мы именуем доменные события») или материал из разговора.
- Развернуть указание в конкретный материал: список файлов или переданное содержимое; концепцию — в её материальный след по репозиторию.
- Определить форму каждой единицы: инструкция, документ, код или тест, след концепции, материал из разговора.
- Поднять только тот локальный контекст, без которого нельзя понять текущий канон.
- Явно пройти полный свод законов Маркова по каждой единице и устранить дубли и противоречия внутри границ.
- Нормализовать цель: файлы переписать на месте, файл без живого содержимого удалить, материал из разговора вернуть нормализованным в чат.
- Сообщить пользователю, какие классы проблем исправлены.

## Связь с конвейером

`markov` стоит вне линейного конвейера и вызывается для конкретной цели. Он может нормализовать `AGENTS.md`, `SKILL.md`, `README.md`, workflow-артефакт, класс, каталог тестов или сквозную конвенцию после работы любого другого скила.

## Почему граница такая

Скил не оценивает всю систему как `audit` и не создаёт новые артефакты. Его сила в точечной нормализации того, на что указали: правки не выходят за развёрнутые границы, даже когда соседний файл болеет тем же.

## Входной контекст

- указание на цель: пути, каталог, glob, концепция или материал из разговора
- полный свод законов Маркова, встроенный в `SKILL.md`
- `AGENTS.md`, если нужен канон репозитория
- соседние workflow-артефакты, если документы зависят от них

## Выходные артефакты

- переписанные файлы внутри границ (опустевшие после нормализации — удалены) либо нормализованный материал в чате
- короткий итог в чат

## Не делает

- Не создаёт отдельный audit-отчёт вместо правки.
- Не меняет файлы вне развёрнутых границ.
- Не работает с внешними ссылками.
- Не меняет поведение кода — только смысл, имена и рамку.
- Не делает git-операции.

## Критерий готовности

Цель описывает достаточное настоящее, не хранит биографию создания и не смешивает разные типы ответственности; правило живёт ровно в одном каноническом месте внутри границ.
