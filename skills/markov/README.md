# markov

## Назначение

`markov` нормализует один переданный локальный документ по законам Маркова. Скил прямо переписывает указанный файл, а не выдаёт рекомендации вместо правки.

## Ответственность

- Принять локальный путь к одному файлу (markdown документ, класс, тест).
- Прочитать документ и определить его тип.
- Поднять только тот локальный контекст, без которого нельзя понять текущий канон.
- Итеративно применить полный свод законов Маркова.
- Переписать переданный документ так, чтобы он был самодостаточным, текущим и без операционного мусора.
- Сообщить пользователю, какие классы проблем исправлены.

## Связь с конвейером

`markov` стоит вне линейного конвейера и вызывается для конкретного документа. Он может нормализовать `AGENTS.md`, `SKILL.md`, `README.md`, `AUDIT.md`, или workflow-артефакт после работы любого другого скила.

## Почему граница такая

Этот скил не оценивает всю систему как `audit` и не создаёт новые артефакты. Его сила в точечной нормализации одного файла, поэтому вход ограничен локальным путём к документу.

## Входной контекст

- путь к локальному документу
- `markov-laws.md` (нужно сохранить в локальную папку скила)
- `AGENTS.md`, если нужен канон репозитория
- соседние workflow-артефакты, если документ зависит от них

## Выходные артефакты

- обновлённый переданный документ
- короткий итог в чат

## Не делает

- Не создаёт отдельный audit-отчёт вместо правки.
- Не меняет связанные документы автоматически.
- Не работает с внешними ссылками.
- Не меняет код проекта.
- Не делает git-операции.

## Критерий готовности

Переданный документ описывает достаточное настоящее, не хранит биографию создания и не смешивает разные типы ответственности.
