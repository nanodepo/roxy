# test

## Назначение

`test` покрывает реализованную фичу тестами, защищающими живые инварианты
поведения. Единственный владелец `./workflow/features/{slug}/tests.md`,
тестового кода фичи и статуса `[*]` в `./workflow/PLAN.md`.

## Место в конвейере

Работает после `implement`. После успешного прогона рекомендует `docs`;
при провале верификации возвращает фичу в `implement` с описанием
сломанного инварианта.

## Входы

- `./workflow/features/{slug}/feature.md`; `plan.md`, `design.md`,
  `NN-task.md`, `tests.md` — если есть.
- Реализованный код фичи и существующая тестовая инфраструктура.
- `./workflow/PROJECT.md` (команды), `ARCHITECTURE.md`, `DESIGN.md`.

## Выходы

- `tests.md` — текущая карта инвариантов и команда/результат верификации.
- Тестовый код в стиле и фреймворке проекта.
- Сверенные соседние тесты: переименованы или удалены те, что описывали
  инциденты и устаревшее поведение.
- Статус `[*]` в `PLAN.md` — только после свежего успешного прогона.
- Финальный closing sweep затронутых артефактов по дисциплине скила `markov`.

## Не делает

- Не меняет продуктовый код.
- Не планирует реализацию и не пишет документацию.
- Не тестирует очевидное: язык, фреймворк, удалённое поведение, историю багов.
- Не выполняет git-операции.

## Когда применять

Фича реализована (`[x]`), и её поведение нужно закрепить проверками:
«test feature», «напиши тесты», «покрой фичу», «проверь фичу».
