# test

## Назначение

`test` покрывает реализованную фичу проверками. Это единственный владелец `tests.md` и тестового кода.

## Ответственность

- Прочитать `feature.md`, `plan.md`, `design.md`, задачи и фактические изменения кода.
- Создать или обновить `./workflow/features/{slug}/tests.md`.
- Описать тесты через инварианты поведения, а не через историю исправления.
- Написать тестовый код.
- Запустить тесты командой из `PROJECT.md` или по обнаруженному тестовому фреймворку.
- Обновить служебный статус фичи в `./workflow/PLAN.md` на `[*]`, если тесты написаны и успешно пройдены.

## Связь с конвейером

`test` работает после `implement`. Его результат читает `docs`; `audit` может проверять полноту покрытия без изменения файлов.

## Почему граница такая

Тесты должны опираться на реализованное поведение, а не на предположения раннего планирования. Поэтому `tests.md` принадлежит только `test`, а статус `[*]` в `PLAN.md` только отражает факт успешного тестового прогона.

## Входной контекст

- `./workflow/features/{slug}/feature.md`
- `./workflow/features/{slug}/plan.md`, если есть
- `./workflow/features/{slug}/design.md`, если есть
- `./workflow/features/{slug}/NN-task.md`, если есть
- реализованный код
- `./workflow/PROJECT.md`

## Выходные артефакты

- `./workflow/features/{slug}/tests.md`
- тестовый код проекта
- обновлённый служебный статус в `./workflow/PLAN.md`

## Не делает

- Не планирует реализацию фичи.
- Не меняет продуктовый код.
- Не пишет документацию.
- Не делает git-операции.

## Критерий готовности

Фича покрыта значимыми проверками, тесты запущены, а статус `[*]` означает фактическое прохождение тестового прогона.
